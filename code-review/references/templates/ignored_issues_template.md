# 已忽略与误报问题清单模板

本文件定义 `ignored_issues.md` 的 Markdown 格式模板，用于记录代码审查中被用户标记为"忽略"或"误报"的问题。

---

## 文件说明

- **文件路径**：`docs/code_reviews/ignored_issues.md`（与审查报告同目录）
- **维护方式**：由代码审查工具自动维护，用户可手动编辑以恢复跟踪某问题
- **作用**：跨次审查持久化已忽略与误报问题，避免定时任务重复报告已知且可接受的问题或已确认不存在的误报问题

### 处理类型说明

| 处理类型 | 含义 | 典型场景 |
|----------|------|----------|
| **忽略** | 问题真实存在，但用户决定不修复 | 已知问题、历史遗留、改动影响面大暂不处理 |
| **误报** | 问题实际不存在，是审查工具误判 | 类型检查器误报、静态分析误判、框架特性被误识别为问题 |

> 两种处理类型在后续审查中均会被跳过，不再重复报告。区别仅在于语义：忽略是"已知且可接受"，误报是"本就不存在"。

## 标记识别规则

工具扫描报告时，按以下规则识别用户标记的处理类型：

### 忽略标记

问题标题中包含以下任一标记，或问题描述/修复建议中包含对应声明，则识别为「忽略」：

- **标题标记**：`（忽略）` / `(ignore)` / `(IGNORE)` / `【忽略】` / `[忽略]` / `[IGNORE]` / `[ignore]`
- **声明语句**：「忽略此问题」「忽略」「不修复」「已知问题，暂不处理」「ignore this issue」「won't fix」

### 误报标记

问题标题中包含以下任一标记，或问题描述/修复建议中包含对应声明，则识别为「误报」：

- **标题标记**：`（误报）` / `(false positive)` / `(FALSE POSITIVE)` / `(FP)` / `(fp)` / `【误报】` / `[误报]` / `[FALSE POSITIVE]` / `[fp]`
- **声明语句**：「误报」「false positive」「工具误判」「非问题」「not an issue」「not a real issue」

> 若同一问题同时包含忽略与误报标记，优先识别为「误报」（误报比忽略更彻底地否定问题存在性）。

## 自动维护规则

1. **首次创建**：当首次有忽略或误报问题产生时，工具自动按本模板创建 `ignored_issues.md` 文件
2. **追加写入**：每次审查完成后，工具扫描新报告，提取新标记为忽略或误报的问题，追加到表格末尾
3. **去重保护**：追加前检查是否已存在相同「文件路径 + 问题标题」的条目，已存在则跳过
4. **手动编辑**：用户可随时手动编辑本文件，删除条目以恢复跟踪；工具仅追加，不删除用户手动保留的条目

---

## 注意事项

- 请勿随意删除表头行，否则工具可能无法正确解析
- 如需批量恢复跟踪多个问题，建议直接删除对应行后保存
- 本文件应与审查报告一起提交到版本控制，以便团队成员共享已忽略与误报问题状态
- 「原报告」字段只记录报告文件名；这些报告在被工具扫描后已归档至 `docs/code_reviews/archived/` 子目录，如需回溯原始上下文，请到 `archived/` 下按文件名查找
