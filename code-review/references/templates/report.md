# 审查报告模板

本文件定义代码审查报告的 Markdown 格式模板，用于生成标准化的审查报告。

---

## 报告命名规则

**文件名格式**：`<检测日期>-<当前大模型的名称>-代码审查报告.md`

**示例**：`2026-05-19-Claude-代码审查报告.md`

---

## 报告保存位置

报告保存位置根据审查场景确定：

| 场景 | 保存位置 |
|------|---------|
| 用户指定 | 按用户要求的路径或方式保存 |
| 本地审查 / 远程对话 | 项目根目录下的 `docs/code_reviews/` 目录 |

**保存示例**：`<项目根目录>/docs/code_reviews/<检测日期>-<当前大模型的名称>-代码审查报告.md`

---

## 报告 Markdown 模板

> **空分类隐藏规则**：如果某级别（如 🔴 严重bug）没有问题，则报告中**不展示**该级别的板块，仅在有问题的级别才输出对应内容。
>
> **不含质量评分**：本报告不包含任何维度的百分制评分或综合评分（如"代码规范性 85/100"）。代码审查的价值在于具体问题与可执行的修复建议，而非主观、无法复现的抽象数字。
>
> **不含改进计划/排期**：本报告不包含按周或按优先级划分的时间排期与工时估算（如"第一周完成高优先级任务"）。修复优先级已由问题分级（🔴/🟠/🟡/🟢）体现，具体排期应由团队根据业务节奏自行决策。
>
> **忽略标记说明**：如认为某个问题无需修复或已知可接受，可在该问题的标题中添加 `（忽略）`、`(ignore)` 或 `【忽略】` 等标记。被标记为忽略的问题将自动记录到 `ignored_issues.md` 清单中，后续自动审查将不再重复报告。详见 `ignored_issues_template.md`。
>
> **误报标记说明**：如认为某个问题是审查工具误判（实际不存在），可在该问题的标题中添加 `（误报）`、`(false positive)`、`(FP)` 或 `【误报】` 等标记。被标记为误报的问题将自动记录到 `ignored_issues.md` 清单中，后续自动审查将不再重复报告。详见 `ignored_issues_template.md`。

## 报告生成步骤

### 步骤 1：准备报告内容

```python
# 报告数据结构示例
report_data = {
    "project_name": "llmakits",
    "review_date": "2026-05-19",
    "review_version": "1.2.3",
    "latest_commit": "abc1234 feat: add new feature",
    "repo_source": "镜像加速（ghproxy）",
    "reviewer": "Reviewer-Claude",
    "issues": {
        "critical": [],
        "warning": [],
        "info": [],
        "minor": []
    }
}
```

### 步骤 2：生成 Markdown 内容

按照模板填充数据，生成完整的 Markdown 内容。

### 步骤 3：保存报告

根据审查场景选择保存方式：
- **用户指定**：按用户要求的路径保存
- **本地审查 / 远程对话**：保存到项目根目录下的 `docs/code_reviews/` 目录（若目录不存在则自动创建）

```
📊 问题统计：
🔴 严重bug：<数量>

🟡 一般问题：<数量>
🟢 轻微问题：<数量>

```

## 注意事项

- 报告必须使用 Markdown 格式
- 表格使用 Markdown 表格语法
- 代码片段使用 Markdown 代码块格式
- 问题描述应具体，包含文件路径和行号
- 提供可执行的修复建议
