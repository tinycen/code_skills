# 子代理并行审查策略

本文件定义在代码审查 Skill 中使用子代理（Subagent / Task）并行执行审查任务的策略。当环境支持多 Agent 并发时，可按本策略拆分任务以缩短整体审查耗时。

> 本策略为**可选执行策略**。环境不支持子代理时，各工作流仍按原有串行步骤执行，不得因缺少子代理能力而中断审查。

---

## 适用场景

以下场景特别适合启用子代理并行审查：

1. **前后端跨仓库联调审查**
   - 前端单仓审查、后端单仓审查、跨仓联调一致性检查三者相互独立，可并行执行。
2. **多仓库批量审查**
   - 用户一次要求审查多个仓库时，每个仓库的审查任务可拆分为独立子代理。
3. **大型单仓多维度审查**
   - 当仓库规模较大且检查维度可拆分时（如按语言、按模块），可考虑拆分；但需权衡上下文分片带来的理解损失，谨慎使用。

---

## 前提条件

启用子代理并行审查必须同时满足：

1. 当前运行环境支持 `Task` 工具或等效的多 Agent 调用能力。
2. 待拆分的任务之间不存在强依赖，结果可在后续步骤中合并。
3. 各子任务所需的输入参数、仓库路径、忽略与误报清单等可在派生前完整确定。

> 若任一条件不满足，应回退到串行执行。

---

## 任务拆分原则

拆分审查任务时遵循以下原则：

| 原则 | 说明 |
|------|------|
| 按仓库拆分 | 不同仓库的代码审查天然隔离，优先按仓库拆分。 |
| 按阶段拆分 | 单仓审查与跨仓联调检查属于不同阶段，可独立并行。 |
| 避免过度拆分 | 同一仓库内不建议按文件或函数粒度拆分子代理，以免损失全局上下文。 |
| 输入独立 | 每个子代理应获得完成任务所需的完整输入，不得依赖运行时共享可变状态。 |
| 输出统一 | 各子代理输出应遵循统一格式，便于主代理合并。 |

---

## 并发边界

### 可并行的步骤

- 不同仓库的代码克隆/更新（网络 I/O 独立）。
- 不同仓库的版本信息获取。
- 不同仓库的单仓代码审查。
- 前端单仓审查、后端单仓审查、跨仓联调一致性检查（在输入准备就绪后）。

### 必须串行的步骤

- **忽略与误报清单加载与合并**：需在所有子代理启动前完成，确保各子代理使用同一套忽略与误报规则。
- **报告最终合并与保存**：需等待全部子代理返回结果后执行。
- **Git 提交与推送**：报告生成完毕后统一执行，避免冲突。

---

## 子代理派生规范

每个子代理应满足：

1. **任务描述清晰**：明确告知子代理审查目标、输入路径、输出格式与合并规则。
2. **上下文最小化**：只传递完成任务所需的文件路径、参数和引用文档，不传递无关上下文。
3. **工具权限可控**：子代理默认只具备读取与生成报告所需权限，禁止执行破坏性操作（如强制推送、删除分支）。
4. **超时与兜底**：为每个子代理设置合理超时；超时或失败时，主代理应记录原因并决定是否重试、降级或终止。

---

## 结果合并

主代理收到各子代理结果后执行：

1. **去重**：合并问题列表时按文件路径 + 问题标题去重。
2. **分级汇总**：分别统计严重 bug、注意问题、一般问题、轻微问题数量。
3. **格式统一**：将各子代理输出转换为当前工作流指定的报告模板格式。
4. **失败处理**：若部分子代理失败，在报告中单独标注「未完成的审查任务」及其原因，不得隐瞒。

---

## 失败降级策略

| 失败场景 | 处理方式 |
|----------|----------|
| 子代理调用能力不可用 | 自动降级为串行执行，记录日志。 |
| 部分子代理超时 | 对超时任务重试一次；仍失败则记录为未完成，继续合并其他结果。 |
| 全部子代理失败 | 终止本次审查并通知用户，附带失败原因。 |
| 子代理输出格式异常 | 尝试解析可用字段；无法解析时标记为失败，不强行合并。 |

## 在跨仓库联调审查中的应用

在 [cross_repo_integration_workflow.md](../cross_repo_integration_workflow.md) 中，执行完「步骤 6：加载已忽略与误报问题清单」后，可按本策略并行派发：

- **子代理 A**：执行前端单仓代码审查（复用 `references/review_process.md`）。
- **子代理 B**：执行后端单仓代码审查（复用 `references/review_process.md`）。
- **子代理 C**：执行跨仓联调一致性检查（复用 `references/cross_repo_integration_checks.md`）。

三个子代理各自完成并返回结构化结果后：
- 子代理 A、B 的单仓审查结果分别保存为独立报告文件，写入各自仓库的 `docs/code_reviews/` 目录。
- 主代理进入「步骤 9：生成联调报告并保存到主仓库」，仅合并联调一致性问题与两端问题统计摘要生成联调报告。

> 单仓审查结果不再合并进联调报告，各自独立输出。联调报告仅含联调问题详情与两端统计摘要，通过路径引用单仓详细报告。

---

## 与现有工作流的关系

- 本策略**不替代**任何工作流，而是作为可选的**执行加速策略**被工作流引用。
- 各工作流在涉及可并行步骤时，应链接到本文件，由执行环境决定是否启用子代理。
